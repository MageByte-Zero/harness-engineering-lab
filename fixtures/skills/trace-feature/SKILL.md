# 功能追踪方法

先确定要解释的功能和问题范围，再取材。当前应用只能只读调查。

1. 使用目录或关键词定位功能入口，读取入口的相关行，确认输入、返回与调用对象。
2. 沿实际调用继续读取实现，确认数据来自哪里、有哪些条件分支。查到调用点并不等于查过被调用实现。
3. 阅读 [核对表](references/acceptance.md)，补查异常及映射；缺少文件或不能确认时保留具体缺口。
4. 把资料中能确认的设计与实时API观察分开。解释静态代码不需要为了展示工具而查询实时状态。
5. 用现有结果契约输出结论、事实依据和缺口，每项事实引用本轮实际读取或业务查询的 observation_id。

方法说明和核对表是做法，不是业务事实，不能成为facts的引用。不得执行项目代码、修改文件、扩大资料范围或代替人工审批。
